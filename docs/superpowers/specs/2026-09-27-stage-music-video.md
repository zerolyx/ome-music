# 私人电台歌词舞台的可选 MV

日期：2026-09-27 · 状态：Bilibili 第一提供方与 360p/480p/720p 画质上限已接入；其他来源与同步深化待后续阶段

## 设计简报

- **意图**：让主动想看画面的听众，在当前音乐和歌词舞台里打开一段匹配视频。
- **问题**：Ome 已有 Bilibili 视频搜索/取流/弹幕链路，但它只用于音频和氛围；舞台还不能展示 MV。
- **方向**：在歌词舞台加一个轻量“MV”入口；只有用户按“搜索 B 站”时才发送曲名和艺人，用户选中结果后才取视频流。
- **层级**：当前歌曲与歌词始终是主层；静音视频作为舞台背景，降低亮度/饱和度；来源选择器是临时工具面板。
- **排版**：保留现有舞台顶栏、字号与歌词结构；桌面选择面板靠右上，窄窗时使用同一视口内的浮层和滚动结果。
- **间距/色彩**：复用现有圆角胶囊控件、玻璃面板、`--bg-elev`、`--accent` 和 `--ease-signature`，不增加媒体资源。
- **交互**：不自动搜索、不预加载；搜索/取流失败只报状态并保留音频；视频静音并跟随现有音频暂停、定位和进度，不改变主音频输出。
- **画质**：用户可将本次舞台会话的 MV 最高画质设为 360p、480p 或 720p，默认 720p；限制只应用于显式选择的 MV 流。播放条中的 Bilibili 音频请求不传画质参数。
- **响应式**：舞台全屏边界不变；窄屏面板宽度受视口约束，控件可换行，页面不横向溢出。
- **复用**：复用 Bilibili 视频候选、媒体 CDN 白名单、Range 代理和播放器 `position/isPlaying` 信号。

## 本批实现范围

- Bilibili 为第一提供方，结果最多显示 12 项；搜索仅由按钮触发。
- 用户明确选择结果后才请求 `/x/player/playurl` 返回的 MP4 DURL；视频走 `ome-media` 代理并沿用现有 CDN 校验。
- 视频随舞台会话存活；收起控制面板只隐藏控件，已选择的视频继续随歌曲播放；用户停止 MV、切换歌曲或退出舞台时释放视频 URL/元素。不写偏好、曲库、历史、队列快照或服务器。
- 浏览器预览和演示 URL 不触发 Tauri/网络调用，显示桌面端提示。
- MV 画质选择映射到 Bilibili `qn` 16/32/64；后端仅接受这三个上限，显示 playurl 返回等级。若返回等级高于上限则拒绝加载；切换上限时重新解析当前候选，失败时保留旧 MV 与音频。

## 后续总账

本批不声称完成 ECHO MV 子系统：本地候选、YouTube/网易云/QQ provider、自动候选排序/预加载和更完整的流协议后续逐项评估；其中自动检索仍须显式授权，DASH/HLS 需要额外架构/解码评估。音乐仍是默认入口和主控时钟。

## 验收

- 状态层覆盖非桌面拒绝调用、显式搜索、选择后才取流、错误保留和歌曲切换丢弃迟到结果。
- StageView 覆盖面板开关、搜索动作、选择与静音视频；搜索无结果或播放失败时歌词/播放器仍可用。
- 测试覆盖画质白名单、命令参数、切换上限后的当前流重新解析及浏览器预览禁用状态。
- 1280×720 与 470×850 截图检查舞台遮挡层级、选择面板滚动/边界和无横向溢出；浏览器预览不发出 Bilibili 请求。
- 本地构建、Lint、前端测试及 Rust 既有验证通过；真实 Bilibili CDN / Tauri WebView 需单独记录是否可端到端验证。
