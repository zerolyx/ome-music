# 已授权本地曲库的按需 MV 候选

日期：2026-09-27 · 状态：本地候选与范围读取已接入；真实 Tauri WebView 验收待桌面运行时

## 目标与边界

当前歌曲仍是主角。本地 MV 是歌词舞台中的可选、静音影像：用户主动开启舞台面板并点击“在本地找 MV”后，才读取当前本地曲目附近的有限目录；选中一个候选后才开始传输视频。操作不启动电台、不更改队列或曲库，不向网络发送查询。

仅为 `source=local`、未按曲库规则排除、音频文件仍可访问且位于已登记音乐目录中的曲目开放目录查找。显式单文件授权只授权该音频文件，不授权枚举其邻居。浏览器演示禁用候选查询/播放。

## 候选发现

- 只浅扫描音频所在目录、其 `MV`/`mv`/`video`/`videos` 直接子目录，以及音频目录父级下的 `MV`/`video` 目录。
- 所有目录必须留在当前已登记音乐根目录下；中间组件、目录或视频文件为符号链接时跳过。
- 每目录最多检查 500 个直接条目；支持 `.mp4`、`.m4v`、`.webm` 且文件非空；候选名按当前曲名和艺人进行确定性评分，最多返回 12 条。
- UI 只显示文件名、字节数和匹配理由，不显示、持久化或发送任何完整文件路径。
- 不递归，不后台扫描，不自动配对，不扫描其他根目录、用户主目录、下载目录、移动盘或网络共享。

## 播放链路

- Rust 为候选生成随机不透明 ID，只将 ID 和展示元数据回传给前端。Registry 只驻当前进程内存，条目 12 小时过期、总量限制 256；播放访问会续期。
- 每个 media 请求解析候选 ID 后，重新验证当前曲目仍存在、来源仍为本地且未排除，当前文件仍位于有效登记目录，候选仍是受支持的常规文件并且未越权/变成符号链接。
- 视频由现有 `ome-media` 协议读取。支持单一 Range，请求响应最多 4 MiB；内容类型固定依据允许的扩展名。错误响应只包含状态码，不返回路径。
- 使用舞台现有静音 `<video>`，音频仍是可听主时钟；跟随音频暂停、播放及 seek。MV 加载失败只清理视频状态和提示，不能停止音乐。
- 切曲、退出舞台、停止 MV 和卸载阶段会清除可见候选/流状态。Rust 的随机候选条目有 TTL，避免浏览器仍持有 URL 时直接泄露路径。

## 实施与验证

- Rust：本地 track/root 授权、限额候选发现、opaque ID registry、Range handler 和临时文件单测。
- 前端：API DTO 不含路径；状态层只在显式请求时调用；按钮只对本地曲目显示且只在桌面可用；结果切换不影响音频电台。
- 验收需覆盖权限拒绝、单文件授权拒绝、已排除/失联曲目拒绝、无关同目录视频过滤、视频 ID 失效、单 Range 与大 Range 限幅，以及浏览器无 Tauri 调用。
- 桌面环境可用时需确认 WebView 视频元素按 Range 实际请求并可 seek；当前临时文件测试不替代 Tauri WebView 端到端检查。

## 已知限制

只接入可直接由 WebView 播放的 MP4/M4V/WebM。MKV、AVI、MOV、容器探测、递归搜索、在线其他 MV Provider、自动候选、DASH/HLS 和帧级同步不在本规格范围。该功能不是媒体库索引，也不改变 Ome 的本地优先 AI 电台与私人 DJ 定位。
